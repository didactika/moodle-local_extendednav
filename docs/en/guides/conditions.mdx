title: Show a node to some people or for a time
summary: Use Moodle's Restrict access on a node, with dates that make it appear and end on its own.

A **Restricted** node can have the **Access restrictions** of Moodle, the same ones as Restrict access of an activity, with or without roles. Open the form of the node, set **Visibility** to **Restricted** and, under **Who sees it**, select **Add restriction**. A node **Visible to everyone** has no limits: it offers no access restrictions, and the ones it had are kept, unused, for when it is restricted again.

| Restriction | What it does |
|---|---|
| **Date** | Shows the node from a date, until a date, or between two |
| **Group** and **Grouping** | Shows the node of a course to the members of a group or a grouping of that course |
| **User profile** | Shows the node to the people whose profile field has a value, such as a department or a city |
| Other restrictions | The ones the plugins of the site add, such as cohorts when that plugin is installed |

Every restriction has to be met, and so does the visibility: a node restricted to some roles and to a group is shown to the people with one of those roles who are in that group. Groups and groupings are offered for the exceptions of a course or an activity, where the node belongs to that course. A **Grade** or the **Activity completion** need the activities of one course, so they are offered only for the exceptions of a course or an activity, never for a node of the whole site or of a category.

## Nodes with dates

A node with a start date appears on its own when the date comes, and a node with an end date disappears on its own when it ends: there is nothing to do on the day. On the management page, the column **Visibility** says:

| Badge | When |
|---|---|
| **Conditions** | Beside **Restricted**: the node has access restrictions; place the pointer over it to read them, or select it to open **Who sees** |
| **Scheduled** | The start date has not come yet |
| **Ended** | The end date has passed; the node stays on the list, hidden, until you change or delete it |

> [!NOTE]
> Administrators see every node by default, also the ones that are scheduled or have ended, marked **Only admins**. See [Administrators see every node](page:concepts/administrators-see-everything).

The restrictions hide the node from the navigation; they do not block the page it links to. To block the page too, use **Block URL access** with a hidden or restricted node.

## When restricted access is turned off

The access restrictions are Moodle's, so they follow **Enable restricted access** in **Site administration > General > Advanced features**, as the ones of an activity do. While it is turned off:

- A node restricted only by access restrictions is shown to everyone, and its URL is not blocked even with **Block URL access**.
- A node restricted by roles and access restrictions is restricted by its roles alone.
- The form does not show **Access restrictions**, and saving a node keeps the ones it has. They apply again as soon as restricted access is turned back on.

To keep a node hidden or its URL blocked while restricted access is off, restrict it by roles or make it **Not visible**.
